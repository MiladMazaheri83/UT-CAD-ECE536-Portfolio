# Automated RTL Synthesis & FPGA Cell Mapping (Yosys Flow)

An automated logic synthesis and technology mapping flow for a simplified **MD5 Hash Generator**, comparing modern open-source EDA synthesis tools against manual fine-grained FPGA cell mapping.

The project translates behavioral RTL Verilog into an intermediate 2-input Look-Up Table (`LUT2`) netlist using **Yosys Open SYnthesis Suite**, followed by a custom mapping pipeline that translates primitive LUTs and flip-flops directly into Actel-like base cells (`c1`, `c2`, `s1`, `s2`).

---

## Synthesis & Technology Mapping Flow

1. **RTL Synthesis (`Yosys`):** 
   - Compiles hierarchical behavioral Verilog into generic logic gates and D-type flip-flops (`$_DFF_P_`, `$_SDFFE_PP0P_`).
   - Uses ABC logic optimization to map all combinational logic strictly into 1-input and 2-input LUTs (`$lut`).
2. **Cell Technology Mapping (`Python / Mapper`):**
   - Direct structural translation of `$lut` primitives into combinational cells (`c1`/`c2`).
   - Structural mapping of sequential primitives (`$_DFF_P_` $\rightarrow$ `s1`, `$_SDFFE_PP0P_` $\rightarrow$ `s2`).
3. **Synthesis Comparison (Manual vs. Automated):**
   - **Project 3 (Manual Structural Mapping):** **2,982 gates** (Met the $\le 4800$ budget constraint).
   - **Project 4 (Yosys + LUT2 Automated Mapping):** **11,039 gates** (Detailed in `syn/numbers.txt`).
   - *Conclusion:* Standard automated generic LUT decomposition introduces significant cell overhead compared to custom-tailored manual datapath and controller optimizations on fine-grained architectures.

## Synthesis & Execution Pipeline

### 1. Run Logic Synthesis with Yosys

The synthesis script compiles RTL sources, performs technology-independent logic optimization, and maps logic trees into `$lut` and generic flip-flop primitives:

```bash
# Execute Yosys synthesis script
yosys -s syn/lut2synth.ys -l syn/yosys_log.txt
```

*Synthesis summary (`syn/yosys_log.txt`):*
- **Total cells generated by Yosys:** 1,121 primitives
  - Combinational LUTs (`$lut`): **1,005**
  - Sequential Cells (`$_SDFFE_PP0P_` + `$_DFF_P_`): **116**

---

### 2. Technology Mapping to Actel Cells

Convert the generic synthesized netlist into target `c1`, `c2`, `s1`, `s2` instances using the Python mapper:

```bash
# Map LUTs to C2 cells and report final gate/cell metrics
python lut2mapper.py src/HashGenerator_lut2.v --cell c2 --count-cells > syn/numbers.txt
```

The resulting gate count (**11,039 cells**) is logged in `syn/numbers.txt`.

## Simulation & Netlist Verification (ModelSim / QuestaSim)

The post-synthesis netlist relies on `data/constant.mem` for round constant initialization.

### Via CLI (Batch Mode)

```bash
# 1. Initialize simulation environment
vlib work

# 2. Compile base cell definitions, synthesized netlist, and testbench
vlog src/base_cells/*.v src/mapped_HashGenerator_lut2.v tb/tb_HashGenerator.v

# 3. Place memory file in simulation working path
cp data/constant.mem .

# 4. Run testbench verification
vsim -c -do "run -all; quit -f" work.tb_HashGenerator
```

---

### Via ModelSim GUI

1. Open **ModelSim** and create a project in the repository root.
2. Add all primitive cell definitions (`c1.v`, `c2.v`, `s1.v`, `s2.v`), the mapped netlist (`src/mapped_HashGenerator_lut2.v`), and `tb/tb_HashGenerator.v`.
3. Copy `data/constant.mem` to the project root directory.
4. Compile all files (`Compile` $\rightarrow$ `Compile All`).
5. Load the testbench: `Simulate` $\rightarrow$ `Start Simulation...` $\rightarrow$ select `work.tb_HashGenerator`.
6. Add waveforms (`clk`, `rst`, `start`, `done`, `data_in`, `hash_out`).
7. Run the verification:
   ```tcl
   run -all
   ```
